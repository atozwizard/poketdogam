# [시스템 상세 설계 사양서] 포켓덱스: 보이스 & 스캔 (Solar AI 기반)

**버전:** 1.0 (2026년 3월 기준 데이터 반영) — superseded  
**핵심 엔진:** Upstage Solar LLM + Upstage Document OCR + Gemini / GPT-4.1 mini  
**주요 대상:** 포켓몬 굿즈(인형, 피규어), TCG 카드, 30주년 기념 데이터

---

## 1. 시스템 아키텍처 (High-Level)

본 시스템은 **Upstage Solar API**를 중앙 두뇌로 삼되, 이미지 인식은 OCR과 외부 멀티모달 모델을 결합한 **'멀티모달 워크플로우'**로 구동됩니다.

1.  **Input Layer:** 모바일 카메라(이미지), 마이크(음성)
2.  **Processing Layer:**
    *   **Upstage Document OCR:** TCG 카드/문서성 이미지의 텍스트 데이터 정밀 추출
    *   **Gemini:** 스캔 이미지 후보 정규화 및 포켓몬 매핑
    *   **GPT-4.1 mini:** 스캔 추론 fallback
    *   **Solar LLM (`solar-pro2`):** 도감 DB와 매칭된 데이터를 기반으로 페르소나 대화 생성
3.  **Output Layer:** 성우 보이스 재생, 3D/AR 모델 렌더링, 도감 상세 정보 표출

---

## 2. 기능별 상세 사양 (Functional Specs)

### 2.1 AI 실물 스캔 엔진 (Upstage OCR + Gemini)
Solar Vision 부재를 전제로, OCR과 멀티모달 추론을 결합한 **'추론형 인식'**을 구현합니다.

*   **포켓몬 카드 스캔 (Upstage Document OCR + Gemini):**
    *   **프로세스:** 카드 촬영 -> Upstage Document OCR이 카드명, HP, 기술, 시리즈 번호 추출 -> Gemini가 오타 교정 및 공식 TCG 데이터베이스 매핑 -> 실패 시 GPT-4.1 mini fallback.
    *   **특징:** 빛 반사나 저화질에서도 OCR 추출 텍스트와 멀티모달 추론을 결합해 카드 종류를 정확히 판별.
*   **포켓몬 굿즈 스캔 (Gemini):**
    *   **프로세스:** 인형/피규어 촬영 -> Gemini가 형태적 특징(색상, 부위별 특징, 포즈)을 추출 -> 도감 데이터와 비교하여 종 판별 -> 실패 시 GPT-4.1 mini fallback.
    *   **특징:** 비정형 굿즈도 특징 기반 추론으로 "이것은 '폼본'의 봉제인형입니다"와 같은 판별이 가능하다.

### 2.2 지능형 도감 비서 '로토 AI' (Solar RAG)
솔라의 긴 문맥 처리 능력을 활용해 할루시네이션(환각) 없는 정보를 제공합니다.

*   **데이터 소스:** `source_guide.md` 기반 1,028종 최신 데이터 + 제10세대 생태 정보.
*   **실시간 코칭:** 유저가 "이 카드랑 어울리는 덱 추천해줘" 혹은 "마스카나의 약점이 뭐야?"라고 질문 시, 솔라가 DB를 참조하여 최적의 전략 답변 생성.
*   **진화 트래커:** "빠르모트로 진화하려면 1,000걸음을 더 걸어야 해!"와 같이 유저의 현재 게임 진행 상태와 연동된 맞춤형 가이드 제공.

### 2.3 멀티미디어 보이스 라이브러리 (Solar Scripting)
성우의 목소리에 영혼을 불어넣는 스크립트 생성기 역할을 수행합니다.

*   **대본 생성:** 솔라가 각 포켓몬의 성격(페르소나)에 맞춰 도감 설명을 구어체로 변환.
*   **음성 매칭:** 생성된 대본에 맞춰 미리 저장된 한국어 성우 보이스(애니메이션 모드) 또는 게임 울음소리(생태 모드) 호출.
*   **예시:** "로토! 방금 스캔한 '게쿠아'는 동남아시아의 맑은 물가에서 온 친구다-로!" (솔라 생성 대본 -> 성우 보이스 출력)

## 3. 데이터 파이프라인 명세 (Data Pipeline)

| 단계 | 모듈 | 상세 동작 및 솔라 활용 |
| :--- | :--- | :--- |
| **인식 (Identify)** | Upstage Document OCR / Gemini | 카드 텍스트 추출 또는 굿즈 특징 추출 및 정규화 |
| **검증 (Verify)** | Gemini / GPT-4.1 mini | 추출된 데이터가 도감 DB(Gen 1-10)와 일치하는지 교차 검증 |
| **합성 (Synthesize)** | Solar LLM (`solar-pro2`) | 유저의 질문 의도 분류 및 도감 기반의 답변 텍스트 생성 |
| **출력 (Output)** | Multimedia Controller | 3D 모델(Unity) 로드 및 성우 음성 파일(WAV) 매칭 재생 |

---

## 4. 구현 시 고려 사항 (Technical Constraints)

*   **속도 최적화:** 실시간 인식을 위해 이미지 압축 후 OCR/멀티모달 API로 전송하고, 인식 중에는 로딩 애니메이션(로토무가 회전하는 연출)으로 체감 대기 시간 관리.
*   **데이터 업데이트:** 2026년 출시될 제10세대 '윈즈·웨이브' 신규 데이터는 솔라의 RAG 시스템에 텍스트 데이터만 추가함으로써 별도의 앱 업데이트 없이 즉시 대응 가능.
*   **보안 및 저작권:** 솔라 API를 통해 생성된 모든 텍스트는 포켓몬 공식 가이드라인을 준수하도록 'System Prompt'에서 강제 제한(필터링).

---

## 5. 솔라 API 특화 활용 전략

Solar API는 챗과 페르소나 응답 생성의 메인 엔진으로 활용하며, 스캔 인식은 별도 OCR/멀티모달 모델로 분리합니다.

1.  **무제한 도감 에세이:** 모든 포켓몬에 대해 솔라가 생성한 "오늘의 포켓몬 생태 이야기"를 매일 유저에게 제공.
2.  **대화형 도감 완성:** 유저가 사진을 찍지 않아도, "노란색이고 귀가 길어"라고 말하면 솔라가 스무고개 방식으로 포켓몬을 찾아 도감에 등록해주는 기능.
3.  **글로벌 대응:** 솔라의 뛰어난 번역 능력을 활용해 한국어 성우 보이스뿐만 아니라 영문/일문 도감 정보도 실시간으로 교차 참조 및 제공.

---

**결론:** 본 명세서는 **Solar Pro 2**를 챗과 콘텐츠 생성의 핵심으로 두고, 이미지 인식은 **Upstage Document OCR + Gemini + GPT-4.1 mini fallback**으로 분리한 현실적인 멀티모달 허브로 정의합니다.










솔라(Solar) API는 기본적으로 **텍스트 중심의 LLM(대규모 언어 모델)**이지만, 최근 업스테이지에서 공개한 솔라 비전(Solar-Mini-Vision) 모델이나 OCR(문서 인식) 기능을 포함하고 있다면 말씀하신 '이미지 인식 기반 도감' 구현이 충분히 가능합니다.
다만, 솔라가 '이미지를 직접 보고 포켓몬 번호를 맞추는 것'보다는 솔라의 추론 능력을 활용해 인식의 정확도를 극대화하는 방식으로 설계해야 합니다. 굿즈와 카드를 나누어 설명해 드릴게요.
1. 포켓몬 카드 인식 (솔라의 주력 분야)
카드는 텍스트 정보가 많기 때문에 솔라를 활용하면 현존하는 어떤 도감 앱보다 정확하게 구현할 수 있습니다.
워크플로우: 카드 사진 촬영 -> 업스테이지 OCR(글자 추출) -> 솔라 API(데이터 정제/추론) -> 도감 매칭.
솔라의 역할:
OCR로 읽어온 파편화된 텍스트(예: "HP 60", "십만볼트", "피카..")를 분석하여 **"이 카드는 1세대 피카츄 카드이며, 시리즈 번호는 CP3입니다"**라고 정확히 판별합니다.
오타 교정: OCR이 "P1kachu"라고 잘못 읽어도 솔라가 문맥상 "Pikachu"로 자동 교정하여 DB 검색 오류를 막습니다.
2. 포켓몬 굿즈(인형, 피규어) 인식 (비전 기능 활용)
인형이나 피규어는 텍스트가 없으므로 솔라 비전(Solar-Mini-Vision) 모델을 사용해야 합니다.
워크플로우: 인형 사진 업로드 -> 솔라 비전(이미지 묘사) -> 솔라 텍스트(포켓몬 판별) -> 도감 매칭.
솔라의 역할:
이미지를 보고 특징을 추출합니다: "노란색 생쥐 모양, 붉은 볼, 번개 모양 꼬리."
추출된 특징을 바탕으로 추론합니다: "이 특징에 부합하는 포켓몬은 '피카츄'입니다."
결과: 단순한 이미지 매칭보다 훨씬 유연합니다. 약간 찌그러진 인형이나 그림자가 진 피규어도 "특징"을 잡아내어 인식률을 높일 수 있습니다.
3. 솔라 API를 활용한 '지능형 인식' 설계 (핵심 노하우)
단순히 "이게 뭐야?"라고 묻는 게 아니라, 솔라의 추론(Reasoning) 능력을 인식 프로세스에 심어야 합니다.
멀티모달 체인(Multimodal Chain):
이미지에서 색상, 형태, 특징점을 텍스트로 먼저 기술하게 합니다. (예: "파란색 개구리, 목에 거품 목도리")
그 텍스트 정보를 솔라의 '도감 지식(RAG)'과 대조합니다.
결과: "이것은 '개굴닌자'입니다." (인식 성공)
질문 기반 보정 (Interactive Scan):
인식이 애매할 경우 솔라가 유저에게 질문을 던집니다: "사진이 흐릿하네요! 이 포켓몬의 꼬리가 불꽃 모양인가요?"
유저의 답변을 받아 최종적으로 도감을 띄워줍니다.
4. 솔라 API 무제한 활용 시나리오 (기획 고도화)
솔라 API를 거의 제한 없이 쓰실 수 있다면, 인식 직후에 다음과 같은 **'데이터 폭탄'**급 경험을 줄 수 있습니다.
실시간 생태 보고서 생성: "방금 스캔하신 '마스카나'는 현재 팔데아 지방에서 가장 인기가 많습니다. 당신의 마스카나는 특히 영리해 보이네요!" (솔라가 즉석에서 생성)
배틀 덱 자동 생성: 스캔한 카드를 기반으로 솔라가 즉시 "이 카드와 함께 쓰면 좋은 서포트 카드 3장"을 추천해 줍니다.
성우 대사 즉석 생성: "피카츄를 스캔하셨군요! 피카츄가 당신에게 '오늘 날씨가 정말 좋아!'라고 인사하고 싶대요." (솔라가 대사 생성 -> TTS 재생)
요약:
텍스트가 있는 카드는 OCR과 결합해 즉시 구현 가능하며, 텍스트가 없는 굿즈는 솔라 비전 기능을 통해 특징을 추출하는 방식으로 구현할 수 있습니다. 솔라의 강력한 추론 능력이 더해지면 단순히 이미지를 찾는 것을 넘어 **"맥락을 이해하는 도감"**이 됩니다.
현재 기준 구현안은 Solar Vision을 전제하지 않고, Upstage OCR과 외부 멀티모달 모델 조합으로 MVP를 진행합니다.

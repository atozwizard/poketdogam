# 포켓덱스 Voice & Scan 데이터 스키마 초안

## 1. 문서 목적
- MVP 구현을 위한 API/DB 스키마를 초안 수준에서 확정한다.
- 기준: `primary_ideation.md` + ideation 통합 분석 결과.

## 2. 설계 원칙
- 단일 진실원: `pokemon_id + form_id` 기준.
- 확장성: 세대/폼/진화 규칙 추가 시 마이그레이션 최소화.
- 추적성: 모든 주요 데이터에 `source`, `version`, `updated_at` 기록.

## 3. DB 스키마 (초안)

### 3.1 핵심 테이블

#### `pokemon_species`
- 목적: 종 단위 기본 정보.
- 컬럼:
  - `pokemon_id` (PK, int)
  - `name_ko` (varchar)
  - `name_en` (varchar)
  - `generation` (smallint)
  - `is_legendary` (bool)
  - `created_at` (timestamp)
  - `updated_at` (timestamp)

#### `pokemon_forms`
- 목적: 폼 단위 상세 정보.
- 컬럼:
  - `form_id` (PK, uuid)
  - `pokemon_id` (FK -> pokemon_species.pokemon_id)
  - `form_name` (varchar)  // base, alola, mega, paradox 등
  - `type1` (varchar)
  - `type2` (varchar, nullable)
  - `height_m` (numeric(4,2), nullable)
  - `weight_kg` (numeric(5,2), nullable)
  - `rarity_tier` (varchar, nullable)
  - `source` (varchar)
  - `updated_at` (timestamp)
- 인덱스:
  - `(pokemon_id, form_name)` unique
  - `type1`, `type2`

#### `pokemon_stats`
- 목적: 폼별 능력치.
- 컬럼:
  - `form_id` (PK/FK -> pokemon_forms.form_id)
  - `hp` (smallint)
  - `attack` (smallint)
  - `defense` (smallint)
  - `sp_attack` (smallint)
  - `sp_defense` (smallint)
  - `speed` (smallint)
  - `bst` (smallint)

#### `evolution_rules`
- 목적: 진화 규칙.
- 컬럼:
  - `rule_id` (PK, uuid)
  - `from_form_id` (FK -> pokemon_forms.form_id)
  - `to_form_id` (FK -> pokemon_forms.form_id)
  - `trigger_type` (varchar)  // level,item,move,friendship,walk
  - `trigger_value` (varchar) // "36", "1000_steps" 등
  - `condition_json` (jsonb)
  - `updated_at` (timestamp)

#### `type_chart`
- 목적: 타입 상성 계산 원천.
- 컬럼:
  - `attack_type` (varchar)
  - `defense_type` (varchar)
  - `multiplier` (numeric(2,2))  // 0, 0.25, 0.5, 1, 2, 4
- 키:
  - `(attack_type, defense_type)` PK

#### `voice_assets`
- 목적: 보이스/사운드 메타데이터.
- 컬럼:
  - `asset_id` (PK, uuid)
  - `form_id` (FK -> pokemon_forms.form_id)
  - `asset_type` (varchar) // character_voice, ecological_sound
  - `asset_origin` (varchar) // official, user_provided, internal_reference
  - `storage_ref` (varchar) // private object key or local mounted path
  - `url` (varchar, nullable) // publishable asset only
  - `duration_sec` (int)
  - `rights_status` (varchar) // licensed, unlicensed_internal, blocked
  - `license_scope` (varchar)
  - `distribution_scope` (varchar) // internal_only, private_test, public
  - `rights_holder` (varchar, nullable)
  - `voice_locale` (varchar, nullable) // ko-KR, ja-JP
  - `voice_actor_name` (varchar, nullable)
  - `is_redistributable` (bool)
  - `is_active` (bool)
  - `updated_at` (timestamp)

#### `users`
- 컬럼:
  - `user_id` (PK, uuid)
  - `email` (varchar, unique)
  - `nickname` (varchar)
  - `created_at` (timestamp)

#### `scan_events`
- 목적: 스캔 이력.
- 컬럼:
  - `event_id` (PK, uuid)
  - `user_id` (FK -> users.user_id)
  - `image_url` (varchar)
  - `top1_form_id` (uuid, nullable)
  - `confidence` (numeric(4,3))
  - `topk_json` (jsonb)
  - `created_at` (timestamp)

#### `discovered_pokemon`
- 목적: 사용자 컬렉션.
- 컬럼:
  - `user_id` (FK -> users.user_id)
  - `form_id` (FK -> pokemon_forms.form_id)
  - `discovered_count` (int)
  - `first_discovered_at` (timestamp)
  - `last_discovered_at` (timestamp)
- 키:
  - `(user_id, form_id)` PK

## 4. ER 관계 요약

```text
pokemon_species 1 --- N pokemon_forms 1 --- 1 pokemon_stats
pokemon_forms 1 --- N evolution_rules (from/to)
pokemon_forms 1 --- N voice_assets
users 1 --- N scan_events
users N --- N pokemon_forms via discovered_pokemon
```

## 5. API 스키마 (MVP)

### 5.1 인증

#### `POST /v1/auth/login`
- request:
```json
{
  "email": "user@example.com",
  "password": "********"
}
```
- response:
```json
{
  "access_token": "jwt",
  "refresh_token": "jwt",
  "user_id": "uuid"
}
```

### 5.2 스캔

#### `POST /v1/scan`
- 설명: 이미지 업로드 후 후보 반환.
- request: `multipart/form-data`
  - `image`: binary
- response:
```json
{
  "event_id": "uuid",
  "top_candidates": [
    { "form_id": "uuid-1", "pokemon_id": 25, "name_ko": "피카츄", "confidence": 0.91 },
    { "form_id": "uuid-2", "pokemon_id": 25, "name_ko": "알로라 피카츄", "confidence": 0.62 }
  ],
  "requires_user_confirmation": false
}
```

#### `POST /v1/scan/{event_id}/confirm`
- 설명: 사용자 확정 후 컬렉션 반영.
- request:
```json
{
  "form_id": "uuid-1"
}
```
- response:
```json
{
  "saved": true,
  "collection_updated": true
}
```

#### `GET /v1/pokedex/search?q=&generation=&type=`
- 설명: 키워드/세대/타입 필터.

### 5.4 상성 계산

#### `GET /v1/battle/type-effectiveness?form_id=uuid`
- response:
```json
{
  "strong_against": ["water", "flying"],
  "weak_against": ["ground"],
  "damage_taken": {
    "ground": 2.0,
    "electric": 0.5
  }
}
```

### 5.5 보이스

#### `GET /v1/forms/{form_id}/voices`
- response:
```json
{
  "assets": [
    {
      "asset_id": "uuid",
      "asset_type": "character_voice",
      "asset_origin": "internal_reference",
      "distribution_scope": "internal_only",
      "voice_locale": "ko-KR",

```

### 5.6 AI 대화

#### `POST /v1/chat`
- request:
```json
{
  "form_id": "uuid",
  "message": "이 포켓몬 진화 조건 알려줘"
}
```
- response:
```json
{
  "answer": "레벨 36에서 진화합니다.",
  "citations": [
    { "source": "evolution_rules", "ref": "rule_id-123" }
  ],
  "confidence": 0.93

```

- response:

## 6. API 오류 규약
- 공통 형식:
```json
{
  "error": {
    "code": "INVALID_FORM_ID",
    "message": "form_id is invalid",
    "trace_id": "uuid"
  }
}
```
- 주요 코드:
  - `UNAUTHORIZED`
  - `VALIDATION_ERROR`
  - `LOW_CONFIDENCE_REQUIRES_CONFIRMATION`
  - `NOT_FOUND`
  - `RATE_LIMITED`
  - `INTERNAL_ERROR`

## 7. 마이그레이션/버전 전략
- DB:
  - semver 방식(`schema_version` 테이블).
  - 파괴적 변경은 새 컬럼 추가 후 단계적 전환.
- API:
  - `/v1` 고정, breaking change는 `/v2`로 분리.
- 데이터:
  - 수집일 기준 스냅샷 테이블 보관(`dataset_snapshot`).

## 8. 오픈 이슈
1. 비배포 음원의 내부 사용 허용 범위와 보관 책임 주체 확정 필요.
2. 폼 분류 임계값(Top-1 auto confirm 기준) 운영값 튜닝 필요.
3. 다국어 명칭 매핑 정책(ko/en/jp 우선순위) 합의 필요.

## 9. 내부 전용 보이스 자산 정책 메모
- 원본 성우 보이스는 저장소에 커밋하지 않는다.
- 비배포 자산은 `voice_assets.storage_ref`로만 연결하고, 공개 URL 생성 기본값은 금지한다.
- `asset_origin != official` 이면서 `rights_status != licensed` 인 자산은 `distribution_scope = internal_only` 로 고정한다.
- 내부 자산은 운영 환경과 분리된 비공개 스토리지 또는 로컬 마운트 경로에서만 참조한다.

# 포켓덱스 구현 아키텍처 확정안

## 1. 목적
- 본 문서는 실제 개발 착수를 위한 구현 기준(LLM, 데이터, 관측성, 구성 방식)을 고정한다.
- 범위: MVP + 확장 가능한 Agentic 구조.

## 2. 기술 스택 확정

### 2.1 모델 전략
- 공통 게이트웨이: `LiteLLM`
- 챗 메인 모델: `solar-pro2`
- 스캔 추론 메인 모델: `gemini`
- 스캔 추론 fallback 모델: `gpt-4.1-mini`
- 문서/OCR 추출: `Upstage Document OCR`
- 라우팅/폴백 규칙:
  - 카드/문서성 이미지에서는 먼저 `Upstage Document OCR`로 텍스트와 구조를 추출한다.
  - 스캔 후보 정규화/매핑은 기본적으로 `gemini`가 수행한다.
  - 스캔 추론 단계에서 아래 임계값 3종 중 하나라도 충족 시 `gpt-4.1-mini`로 fallback:
    - `timeout(ms)` 초과
    - `error code` 발생(5xx, provider error, rate limit)
    - `quality score` 임계값 미만
  - 챗 응답 생성은 기본적으로 `solar-pro2`가 수행한다.
  - fallback 발생 이벤트는 Langfuse 태그(`llm_fallback=true`)로 기록한다.

### 2.2 데이터 계층
- 주 DB: `Supabase PostgreSQL` (Auth + Storage + pgvector)
- 보조 DB:
  - `Graph DB` (엔티티 관계: 포켓몬-폼-타입-진화-서식 연결)
  - 무료 티어 우선 원칙으로 초기 후보는 `Neo4j Aura Free` 권장
- 검색/추론:
  - `Hybrid GraphRAG`
  - `Supabase pgvector` 벡터 검색 + Graph DB 탐색 결과 합성.
  - 참고: Supabase는 PostgreSQL 기반이며, 본 프로젝트의 기본 RDB로 확정.

### 2.3 외부 API
- 위치 기반 날씨: `OpenWeatherMap`
- 날씨 반영 챗:
  - 현재 위치 날씨를 챗 컨텍스트에 주입.
  - 예시: 비/눈/고온 조건에서 대화 톤 변경 + 추천 로직(포켓몬/활동) 모두 반영.

### 2.4 관측성/트레이싱
- `Langfuse` 사용
- 수집 항목:
  - 프롬프트/응답
  - 토큰 사용량(input/output)
  - latency
  - tool call 결과
  - fallback 여부
  - 사용자 세션/trace id
  - 정책: 프롬프트 전문 저장 허용(개인정보 미사용 원칙 전제)

### 2.5 설정/비밀키 관리
- 최상위 `config`에서 `.env` 참조
- 원칙:
  - 코드 내 하드코딩 금지
  - provider key 분리(`UPSTAGE_API_KEY`, `GEMINI_API_KEY`, `OPENAI_API_KEY`, `SUPABASE_URL`, `SUPABASE_KEY`, `OPENWEATHERMAP_API_KEY`, `LANGFUSE_*`, `LITELLM_*`)
  - 환경별 `.env` 파일 분리(`.env.local`, `.env.dev`, `.env.prod`)

## 3. 애플리케이션 구조 확정

핵심 플레이트는 `Graph`, `State`, `Tool`, `Node` 구조로 고정한다.

```text
app/
├─ config/
│  ├─ settings.py                # .env 로딩, 전역 설정
│  └─ providers.py               # LLM/DB/API 클라이언트 팩토리
├─ agents/
│  └─ pokedex_agent/
│     ├─ graph.py                # 전체 워크플로우 그래프 정의
│     ├─ state.py                # 상태 스키마 정의
│     ├─ nodes/
│     │  ├─ ingest_input.py
│     │  ├─ detect_location_weather.py
│     │  ├─ extract_scan_text.py
│     │  ├─ retrieve_hybrid_graphrag.py
│     │  ├─ compose_answer.py
│     │  ├─ fallback_scan_model.py
│     │  └─ persist_trace.py
│     └─ tools/
│        ├─ tool_supabase.py
│        ├─ tool_graphdb.py
│        ├─ tool_upstage_document_ocr.py
│        ├─ tool_weather.py
│        └─ tool_langfuse.py
├─ schemas/
│  ├─ api.py
│  └─ domain.py
└─ api/
   └─ routes/
      ├─ chat.py
      ├─ scan.py
      └─ pokedex.py
```

## 4. 상태(State) 모델 초안
- `session_id`
- `user_id`
- `input_text`
- `location` (lat/lon/city)
- `weather` (condition/temp/humidity)
- `intent`
- `scan_text`
- `entities` (pokemon/form/type/evolution keyword)
- `retrieval_context` (vector hits + graph path)
- `llm_provider_used`
- `llm_model_used`
- `fallback_used`
- `response_text`
- `trace_id`
- `error`

## 5. 노드(Node) 책임 분리
- `ingest_input`: 입력 정규화, intent 초분류.
- `detect_location_weather`: 위치 해석 후 OpenWeatherMap 조회.
- `extract_scan_text`: 카드/문서성 이미지에서 Upstage OCR 추출.
- `retrieve_hybrid_graphrag`: Supabase + Graph DB 동시 조회.
- `compose_answer`: 챗 응답 생성(기본 `solar-pro2`).
- `fallback_scan_model`: 스캔 추론 실패 시 `gpt-4.1-mini`로 재생성.
- `persist_trace`: Langfuse에 trace/span/token 기록.

## 6. 도구(Tool) 계약 규칙
- 모든 Tool은 I/O 스키마를 명시한다.
- timeout/retry 기본값을 가진다.
- Tool 실패 시 state의 `error`에 구조화 기록.
- 민감 정보는 Tool 레벨에서 마스킹 후 로깅.

## 7. 에러 및 fallback 정책
- 스캔 추론 실패:
  - `gemini` 실패 시 `gpt-4.1-mini` 1회 fallback.
  - 임계값 3종(timeout, error code, quality score) 병행 적용.
  - 재시도 실패 시 후보 축소 또는 사용자 수동 선택 유도.
- 챗 실패:
  - `solar-pro2` 실패 시 안전 응답 + 사용자 재질문 유도.
- Weather API 실패:
  - 날씨 없는 기본 챗으로 degrade.
- GraphRAG 실패:
  - 벡터 검색만으로 축소 동작(degraded mode).

## 8. 구현 우선순위
1. config/.env 및 provider 팩토리(LiteLLM 포함)
2. state 정의 + graph skeleton
3. tool(supabase/graph/upstage-ocr/weather/langfuse)
4. node 연결 + 스캔 fallback/quality 게이트
5. API 라우트 연동
6. 관측성 대시보드 점검

## 9. 확정된 운영 정책
1. Graph DB: 무료 티어 우선(초기 `Neo4j Aura Free` 권장, 추후 데이터 규모 보고 재평가)
2. 벡터 저장소: `Supabase pgvector` 사용
3. 날씨 반영: 대화 톤 + 추천 로직 모두 반영
4. 스캔 fallback 임계값: timeout/error code/quality score 3종 모두 사용
5. Langfuse 저장 범위: 프롬프트 전문 허용
6. 멀티턴 메모리: 로그인 사용자 기준 영구 저장(부하 증가 시 7일 TTL로 축소)
7. 배포: 단일 리전 시작

## 10. Python 실행 규칙
- 모든 `.py` 파일은 단독 실행 가능해야 한다.
- 각 파일 상단에 직접 실행 명령 주석을 둔다.
- 권장 형식:
  - `# Run: python path/to/file.py`
  - `if __name__ == "__main__": main()`

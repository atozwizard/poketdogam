# 내부 전용 보이스 자산 운영안

## 1. 목적
- 국내 성우 보이스를 초기 개발본에서 참조하되, 제품 코드와 비배포 자산을 분리한다.
- 비공개 자산의 저장, 연결, 노출 통제를 문서 기준으로 고정한다.

## 2. 적용 범위
- `voice_assets.asset_type = character_voice`
- `asset_origin in (user_provided, internal_reference)`
- `rights_status in (unlicensed_internal, blocked)` 또는 공개 배포가 허용되지 않은 모든 음성 자산

## 3. 운영 원칙
- 저장소에는 음원 파일 자체를 커밋하지 않는다.
- 앱은 음원 다운로드 기능을 제공하지 않고, 이미 확보된 내부 자산의 메타데이터만 읽는다.
- 비배포 자산은 기본값으로 `distribution_scope = internal_only`, `is_redistributable = false` 처리한다.
- 공개 배포 빌드에서는 `distribution_scope != public` 자산을 조회 결과에서 제외한다.

## 4. 권장 저장 구조
```text
private_assets/
└─ voices/
   └─ ko-KR/
      └─ {pokemon_id}/
         └─ {form_id}/
            ├─ character_voice_01.wav
            └─ manifest.json
```

## 5. 메타데이터 필수 항목
- `form_id`
- `asset_type`
- `asset_origin`
- `storage_ref`
- `rights_status`
- `distribution_scope`
- `voice_locale`
- `is_redistributable`
- `updated_at`

## 6. 애플리케이션 가드레일
- 서버 API는 공개 클라이언트에 `internal_only` 자산의 실제 경로를 반환하지 않는다.
- 내부 QA 빌드만 로컬 마운트 또는 비공개 스토리지 자격증명으로 접근한다.
- 로그에는 실제 파일명 대신 `asset_id`와 `form_id`만 남긴다.

## 7. 후속 작업
1. `voice_assets` 마이그레이션 정의
2. 내부/공개 빌드별 보이스 필터링 규칙 추가
3. 비공개 자산 마운트 경로를 `.env` 기반 설정으로 분리

## 결론

- 기존 238폼·714건 Top-3 94.54%는 간접 참조 이미지의 합성 변형 회귀이며
  실물 인형·카드·사용자 카메라 정확도가 아니다.
- 오픈 라이선스 사용자 촬영 파일럿에서 제품 경로 Top-3는 2.94%,
  confidence threshold 전 원시 시각 순위 Top-3는 5.88%였다.
- 학습/평가 이미지를 분리하고 현장 프로토타입을 보강한 실험은
  17.65%에서 79.41%로 61.76%p 개선됐지만 90%에는 미달했다.
- 1세대 전체 정확도 90%는 달성하거나 주장하지 않는다.

## 인식 개선 실험

- 제품 경로는 전체 프레임과 중앙 68%·56% 3뷰를 유지했다. 21개 grid view를
  제품 경로에 적용해도 threshold 통과 후보는 0%이고 지연만 증가해 반영하지
  않았다.
- 벤치 전용으로 34개 학습 사진에서 714개 multiscale crop 임베딩을 만들고,
  다른 34개 사진을 holdout으로 평가했다.
- 최근접 프로토타입 Top-3가 79.41%로 가장 높았다. 색 히스토그램 k-NN은
  70.59%, 선형 ridge 분류 헤드는 76.47%, centroid는 58.82%여서 채택하지
  않았다.
- 데이터가 9종·동일 촬영 시리즈에 편중되어 프로토타입을 제품 DB에 넣으면
  과적합을 배포하는 셈이므로 실험 결과로만 보존했다.
- Android 카메라에는 중앙 사각 프레임과 “대상을 프레임의 70% 이상 채우기”
  안내를 추가해 현재 3뷰 추론의 촬영 조건을 사용자가 맞출 수 있게 했다.

## 95점 개선 구현

- 기존 미커밋 기준선을 `9776f4a`로 커밋·푸시한 뒤 변경을 시작했다.
- 웹 도감 렌즈 안에 `getUserMedia` 후면 카메라 프리뷰, 명시적 사진 촬영,
  촬영본 확인 후 분석, 갤러리 복구 경로를 구현했다.
- 카메라 프레임의 밝기·반사·선명도 피드백을 독립 JavaScript 모듈과
  단위테스트로 구현했다.
- 피카츄와 같이 동점 폼이 많은 이름 검색에서 기본 폼을 우선하고,
  confidence를 확률이 아닌 `후보 점수`로 표시하도록 웹·Android를 통일했다.
- 참고 PNG 4개를 웹 정적 경로에서 제거해 공식 미디어 미포함 경계를 복원했다.
- 이미지 분석을 이벤트 루프 밖에서 실행하고 동시 분석 용량, 4천만 픽셀 제한,
  타임아웃, 보안 헤더, liveness/readiness, 로컬 런타임 메트릭을 추가했다.
- Dex schema v1, 필수 인덱스, SHA-256 manifest, 원자적 게시, Android
  SHA-256 설치/교체 및 Release R8 설정을 추가했다.
- Node 2건, Python 47건, Kotlin 2건을 통과했고 Android lint·Debug APK·계측
  테스트 APK·Release AAB 빌드를 통과했다.
- Openverse에서 1세대 151종 각각의 toy/figure, plush, card 검색을 모두
  수행했으나 엄격한 공개 라이선스·단일 종·물리 물체 조건을 만족한 신규
  후보는 1건뿐이었다. 로컬 후보는 69건·10종이며 신규 1건은 검수 전이므로
  기존 68건 벤치에 포함하지 않았다.
- 2.15GB 규모의 1세대 149종 외부 혼합 이미지 후보를 로컬 `data/raw`에

# **Agentic Workflow 설계서**

## \[포켓덱스 Voice & Scan\] 가칭: 로토무 도감 에이전트

# **1. 서비스 개요**

실물 포켓몬 굿즈(카드/피규어/인형)를 스캔하면 해당 포켓몬 데이터(도감, 폼, 진화, 상성, 사운드, 대화)를 즉시 연결하는 멀티모달 도감 워크플로우를 설계한다.  
핵심은 `스캔 인식 -> 데이터 정규화 -> 검증 -> 사용자 확인 -> 저장/추천`의 에이전트형 자동화다.

### **1.1 핵심 목적**

Step 1: 사용자에게 제공할 가치 선별

| 분석 질문 | 답변 (포켓덱스 에이전트 기준) |
| :---- | :---- |
| 에이전트 없이 이 작업을 하려면 사용자가 뭘 해야 하나요? | 포켓몬 이름 추정, 도감 사이트 수동 검색, 폼/진화 조건/상성을 각각 다른 페이지에서 찾아 교차 확인해야 함. |
| 그 작업에 얼마나 시간이 걸리나요? | 건당 평균 3-8분, 정확한 폼 판별 필요 시 10분 이상. |
| 그 과정에서 사용자가 힘들어하는 점은? | 유사 외형(리전폼/메가/패러독스) 오인식, 정보 출처 불일치, 모바일 검색 피로. |
| 에이전트가 대신하면 얻는 점은? | 5초 내 결과 확인, 동일 ID 체계 기반 정합성 확보, 수집/학습/대화 경험 연속화. |

Step 2: 핵심 목적 문장

**\[실물-디지털 정보 단절\]**을 해결하여 사용자가 **\[복수 사이트 수동 탐색\]** 없이  
**\[스캔 한 번으로 신뢰 가능한 도감 정보와 상호작용\]**을 즉시 얻는 **\[로토무 도감 에이전트 워크플로우\]** 구축.

Step 3: 핵심 효용 구체화

- 인식 자동화: 이미지에서 포켓몬 후보를 추출하고 폼 단위까지 식별.
- 정보 통합: 종/폼/진화/타입/상성/사운드/대화 컨텍스트를 하나의 응답으로 합성.
- 품질 보장: 신뢰도 점수 기반 재질문/후보 제시로 오인식 최소화.

### **1.2 해결 과제**

Step 1 & 2: 해결 과제 식별 및 중요도

| 과제 | 중요도 | 이유 |
| :---- | :---- | :---- |
| 폼 오인식(리전폼, 메가진화, 패러독스) | Critical | 같은 종 기반 다른 형태를 잘못 매핑하면 핵심 가치 훼손. |
| 데이터 소스 불일치 | Critical | 출처별 수치/명칭 차이로 사용자 신뢰도 하락. |
| 추론 과잉(할루시네이션) | High | 존재하지 않는 진화 조건/스탯 제시 위험. |
| 응답 지연 | High | 스캔 UX에서 3초 이상 지연 시 이탈 증가. |
| 라이선스/권리 이슈 | High | 음성/이미지/캐릭터 자산 사용 제한 가능. |

Step 3: 해결 방안

- 과제 1: 폼 오인식 대응 \[Critical\]
  - 2단계 판별: 종 식별 -> 폼 분기 분류.
  - 임계값 미달 시 Top-3 후보+차이점 안내, 사용자 선택 확정.
- 과제 2: 데이터 불일치 대응 \[Critical\]
  - Canonical DB(`pokemon_id + form_id`)를 단일 진실원으로 사용.
  - 외부 자료는 출처, 수집일, 신뢰등급 메타데이터 동시 저장.
- 과제 3: 추론 과잉 대응 \[High\]
  - 생성형 응답은 근거 필드가 없는 값 출력 금지(Guardrail).
  - 불확실 항목은 "미확정" 레이블 강제.

### **1.3 주요 기능**

| 서비스 기획 기능 | 워크플로우 모듈 | 상세 설명 |
| :---- | :---- | :---- |
| 실물 스캔 인식 | Vision Inference | 카메라 입력에서 종/폼 후보 추출, bbox/feature 임베딩 생성 |
| 카드 텍스트 파싱 | OCR + Parser | 카드명/번호/기술 텍스트 추출 후 표준 스키마 매핑 |
| 도감 조회/정규화 | Entity Resolver | `pokemon_id`, `form_id`, 세대, 타입, 특성, 진화 조건 결합 |
| 상성/전략 계산 | Battle Rule Engine | 18타입 상성 계산, 추천 대응 타입/기술 생성 |
| AI 파트너 대화 | Persona Chat Agent | 포켓몬 페르소나 기반 질의응답, 진화 코칭 |
| 컬렉션 반영 | Memory/Store | 스캔 이력 저장, 발견 도감/즐겨찾기/학습 기록 갱신 |
| 품질 제어 | Guardrail Validator | 근거 필드 누락, 스키마 위반, 저신뢰 응답 차단 |

### **2. 시스템 아키텍처**

### **2.1 사용자-시스템 상호작용**

1. 사용자 스캔 입력(이미지/카드/텍스트 질문).
2. 시스템이 후보 인식 및 신뢰도 계산.
3. Canonical DB와 참조 데이터 조회 후 결과 합성.
4. 사용자에게 즉시 응답 및 액션(저장/재질문/대화) 제시.
5. 사용자 선택 결과를 학습/메모리에 반영.

### **2.2 워크플로우 흐름도**

```text
[Capture]
  -> [Preprocess]
  -> [Vision/OCR Inference]
  -> [Entity Resolver]
  -> [Data Retrieval]
  -> [Rule Engine]
  -> [Guardrail Validation]
  -> (Low confidence?) -> [Ask Clarification] -> [Entity Resolver]
  -> [Response Composer]
  -> [Save Collection + Analytics]
```

## **3. 워크플로우 상세 설계**

### **3.1 이용자 관점 흐름**

1. 메인 화면에서 `스캔`.
2. 1-3초 내 결과 카드 표시(포켓몬명/폼/신뢰도).
3. 확정 후 상세: 진화, 상성, 사운드, AI 대화 버튼.
4. `내 컬렉션` 자동 반영 및 재방문 추천.

### **3.2 시스템 관점 흐름**

1. 이미지 정규화(해상도, 밝기, 배경 노이즈).
2. 분류 모델 inference 및 Top-K 후보 생성.
3. 후보별 지식베이스 조회 후 일치도 재랭킹.
4. Rule Engine으로 전투/진화 계산값 생성.
5. Guardrail로 누락/모순 검사 후 응답 직렬화.

### **3.3 노드별 상세 명세**

| 노드 | 입력 | 출력 | 실패 시 처리 |
| :---- | :---- | :---- | :---- |
| Capture | raw image | image blob | 업로드 재시도 |
| Preprocess | image blob | normalized image | 기본값 파이프라인 적용 |
| Vision/OCR | normalized image | 후보 리스트+confidence | OCR/모델 fallback |
| Entity Resolver | 후보 리스트 | canonical entity | Top-3 확인 질의 |
| Data Retrieval | entity id | 도감/폼/진화/사운드 | 캐시 fallback + 누락 레이블 |
| Rule Engine | entity + context | 상성/전략 결과 | 계산 불가 시 설명형 응답 |
| Guardrail | composed payload | validated payload | 차단 후 재생성 |
| Response Composer | validated payload | UI response JSON | 최소 응답 템플릿 |
| Save/Analytics | response + event | 저장 결과 | 비동기 재시도 큐 |

### **4. 구현 전략**

### **4.1 핵심 전략 영역**

- 데이터 전략:
  - Canonical schema 우선 확정(`pokemon`, `form`, `evolution`, `type_chart`, `media_asset`).
- 모델 전략:
  - 1차 분류 모델 + 2차 폼 판별 모델 분리 배포.
- UX 전략:
  - 저신뢰 시 자동 정답 생성 금지, 사용자 확인 경로 우선.
- 운영 전략:
  - 모델 버전/데이터 버전 동시 로깅으로 이슈 추적 가능하게 설계.

## **5. 구현 시 고려 사항**

### **5.1 비용 및 응답시간 분석**

- 목표 응답시간:
  - 스캔 결과 2.5초 이내(P95), 상세 응답 1.5초 이내(P95).
- 비용 주요 항목:
  - Vision inference, OCR API, LLM 토큰, 미디어 CDN.
- 최적화:
  - 결과 캐시, 경량 모델 우선 호출, 상세 정보 지연 로딩.

### **5.2 안정성 및 위험 관리 대응**

- 품질 지표:
  - Top-1 정확도, 폼 분류 정확도, 사용자 재선택율, 오답 신고율.
- 운영 정책:
  - 장애 시 읽기 전용 모드(검색 기반 도감) 자동 전환.
- 보안/권리:
  - 음성/이미지 자산 라이선스 범위별 노출 정책 분리.

### **5.3 의도적 제외 기능 리스트**

- 실시간 대전 매칭/랭킹 시스템.
- 유저 간 거래/마켓플레이스.
- 비공식 유출 데이터 자동 반영.
- 음성 합성(TTS) 기반 공식 성우 대체 기능.

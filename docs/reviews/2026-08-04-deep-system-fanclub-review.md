## 4. 한국 포켓몬 팬클럽 회장의 다각도 리뷰

1. **수집가:** 세대별 진행률은 애착의 시작이다. 다음은 중복 폼, 획득일,
   즐겨찾기, 로컬 내보내기 포맷을 데이터 소유권 관점에서 다듬을 차례다.
2. **한국 카드 팬:** 카드명 밴드 UX는 좋지만 실물 한글 카드 데이터 없이
   “카드도 된다”는 표현을 앞세우면 신뢰를 잃는다.
3. **최신 세대 팬:** 1–9세대 라벨보다 Gen7–9 실패 시나리오와 실제 게임
   캡처 검증이 더 중요하다.
4. **학부모·개인정보:** 원본 미저장, 삭제 가능, 로컬 저장은 강한 장점이다.
   이 정책은 기능 뒤에 숨기지 말고 현재처럼 촬영 직전에 노출해야 한다.
5. **접근성:** 360px과 터치 흐름은 통과했지만 실기기 TalkBack, 큰 글자,
   저조도, 손떨림 사용자 시나리오는 별도 검증해야 한다.
6. **경쟁·정보 신뢰:** ranking score를 확률로 오해하지 않게 한 것은 필수다.
   후보를 왜 보여줬는지 OCR/외형 근거를 간단히 비교할 수 있으면 더 좋다.
7. **커뮤니티:** 종·매체·세대별 갭을 공개하고, 기여자 출처·라이선스·
   삭제 요청 경로를 투명하게 운영해야 팬 기여가 지속된다.
8. **브랜드·라이선스:** 로토무 말투와 포켓몬 명칭은 PoC의 매력이지만,
   정식 승인 전 상용화해서는 안 된다. 현재의 비상업·공식 미디어 미포함
   경계를 유지해야 한다.

## 5. 자기검토·자기비판·자기수복

- **자기검토:** 전에는 스크립트가 낸 `certified=true`를 원시 지표보다 먼저
  믿었다. 이번에는 질의가 실제 제품 추론과 동일한지, 평가 매체가
  실제로 존재하는지를 역으로 확인했다.
- **자기비판:** 테스트가 잘 통과해도 오류 정의 자체가 틀리면 PASS는
  무의미하다. 코드 존재 점수를 현장 정확도로 대체한 것이 가장 큰 실패였다.
- **자기수복:** 인증 스키마를 v3으로 바꾸고, 세 근거를 API·UI·문서·
  테스트 오라클까지 관통시켰다. 과거 PASS 문서는 삭제하지 않고
  정정 배너를 붙여 추적 가능성을 남겼다.
- **잔여 한계:** 자동화는 새로운 실물 표본, Android 실기기, 정식 라이선스를
  만들어내지 못한다. 이 세 가지는 미확인으로 남긴다.

Python 3.13에서 간헐적으로 보인 SQLite `ResourceWarning`은 세 수집 스크립트의

해소했다. Starlette `TestClient` deprecation은 비차단 기술 부채로 남기며
후속으로 `httpx` ASGI transport 전환을 진행한다.

엔지니어링 통합 테스트가 PASS해도 `system_test_authorized=false`는 정상이다.
전자는 시스템이 연결되었다는 뜻이고, 후자는 제품 정확도·커버리지
게이트까지 충족했다는 뜻이다.

## 7. 11:38 스레드·락·수명주기 추가 감사와 수복

요청 수신부터 SQLite 저장, 시각 추론, Android 카메라 콜백, 앱 종료까지
동시에 실행될 수 있는 경로를 스레드 단위로 다시 추적했다. 알려진 P0 코드
결함은 수복 후 0건이다.

| 경합 지점 | 실패 형태 | 수복 | 회귀 증거 |
| :-- | :-- | :-- | :-- |
| 동일 새 `session_id` 동시 요청 | 두 요청이 모두 미존재를 보고 PK 충돌 | `BEGIN IMMEDIATE`로 생성·만료 초기화를 원자화 | 16개 동시 `ensure`에서 행 1개 |
| 동일 세션 동시 대화 | 늦은 응답이 최신 `flow_state`를 덮음 | `turn_count` 낙관적 버전 검사; 대화 4턴은 보존하고 오래된 상태만 미적용 | stale exchange 회귀 PASS |
| 세션 삭제와 스트림 종료 | 삭제 후 늦은 저장이 세션을 되살리거나 FK 오류 | 삭제와 교환 저장 모두 즉시 쓰기 트랜잭션; 삭제된 세션은 재생성 금지 | delete-race 회귀 PASS |
| 유휴 TTL | 새 요청이 없으면 평문 대화가 남음 | 앱 lifespan의 60초 주기 정리 + 요청 경로 정리 | 만료 대화 삭제 회귀 PASS |
| Python 매처 singleton·참조 캐시 | 동시 초기화 중복, DB 원자 교체 뒤 오래된 행 사용 | double-checked lock, 캐시 lock, inode·mtime 기반 아티팩트 fingerprint | 32-thread singleton·DB replace PASS |
| 서버 스캔 중첩 | 느린 네이티브 추론이 요청 큐를 늘림 | event loop 외 실행, 단일 bounded capacity, 1초 후 429 | 느린 스캔 중 health 응답·중첩 429 PASS |
| 예외 계측 | middleware 밖 500이 오류 지표에서 누락 | 예외 경로도 latency·route·error를 원자 집계 | 강제 500 계측 PASS |
| Android 연속 탭 | 여러 executor·recognizer와 역순 UI 덮어쓰기 | in-flight 버튼 잠금, 15초 watchdog, 단일 완료 CAS | Kotlin compile·lint 및 정적 계약 PASS |
| Android 종료 대 추론 | `ImageEmbedder.close()`와 `embed()`가 충돌 | lifecycle lock, non-blocking close 요청, 추론 종료 시 자원 회수 | Kotlin compile·lint PASS |
| SQLite 스크립트 연결 | context manager가 commit만 하고 close하지 않음 | `contextlib.closing`으로 세 수집 스크립트 명시 종료 | `ResourceWarning` 오류 승격 회귀 PASS |

잔여 스레드 한계는 네이티브 MediaPipe/OCR 호출 자체가 OS 수준에서 무한
정지할 경우 Python 스레드를 강제 종료할 수 없다는 점이다. 서버는 bounded
capacity로 메모리 폭증을 막고 다른 API는 계속 응답하며, Android는 watchdog과
앱 재시작 복구를 제공한다. 장시간 soak에서 실제 hang이 재현되면 추론 전용
자식 프로세스와 watchdog 재기동으로 격리하는 것을 P2 운영 조건으로 둔다.

## 8. 95/100을 진짜로 만족하기 위한 완료 조건

코드 체크를 더 추가하거나 배점을 바꿔서는 95가 되지 않는다. 현재 자동화·
DB·UI·인프라는 각 100이지만, 실제 증거를 넣은 종합은 **65.3**이다.
다음 조건을 모두 채워야 `system_test_authorized=true`로 바뀐다.

1. **제품 무힌트 탐색:** 1–9세대 1,025종을 세대 힌트 없이 평가해 Top-3를
   69.63%에서 90% 이상으로 올린다. 동일 원본의 변형을 참조와 평가에 나누지
   않고, source/creator 단위 holdout과 hard-negative 세트를 사용한다.
2. **매체 독립 검증:** 현재 1종에서 최소 4종으로 늘린다. 인게임·한국어 카드·
   인형/피규어·굿즈/스티커/실제 사용자 스크린샷을 매체별로 분리 보고하고,
   낮은 매체를 평균으로 숨기지 않는다.
3. **1세대 실물 필드 인증:** 28종→151종, 91장→453장, 20명→30명 이상으로
   확대하고 제품 경로 Top-3를 9.89%→90% 이상으로 올린다. 종별 최소 3장,
   촬영자/장소/기기 분리, 한 촬영자 편중 방지, 라벨·라이선스 이중 검수를
   동시에 만족해야 한다.
4. **모델·검색 개선:** 배경 제거/대상 crop, 매체별 다중 참조, hard-negative
   mining, 품질별 임계값, OCR 이름 밴드와 외형 점수의 검증된 fusion을 적용한
   뒤 같은 잠금 holdout을 한 번만 최종 평가한다. 정답 세대 힌트 91.8%는
   제품 점수로 승격하지 않는다.
5. **출시 증거:** 한국어 실물 카드 30장 알파와 100장 MVP, 중급 Android
   실기기 CameraX·ML Kit·MediaPipe, TalkBack/큰 글자/저조도/손떨림,
   장시간 카메라·세션 soak, 정식 IP 라이선스를 별도 통과한다.
6. **회귀 기준:** Python/JavaScript/Kotlin 단위·API 통합 실행 성공률 97%
   이상, Android 계측 실기기 성공, SQLite·아티팩트 무결성, 개인정보 삭제,
   출처 추적을 매 커밋에서 재검증한다. 이번 코드 회귀는 Python 63/63,
   JavaScript 3/3, Kotlin 2/2로 **100%**다. Android 계측 1건은 APK 빌드만
   검증됐으므로 실기기 실행 성공률에 포함하지 않는다.

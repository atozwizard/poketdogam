# 문서 변경 관리 규칙 (docs/rules)

## 1. 목적
- 본 문서는 프로젝트 문서의 변경/반영/이력 기록 규칙을 정의한다.
- 이 문서는 진행상황에 따라 수정 가능하다.

## 2. 적용 범위
- `docs/` 하위 전체 문서
- 기획, 아키텍처, 스키마, 로그, 규칙 문서

## 3. 변경 원칙
1. 문서 변경 시 반드시 `수정 일자`와 `수정 내역 요약`을 기록한다.
2. 부분 수정이 발생하면 관련 문서 전체에 일관되게 반영한다.
3. 결정사항이 바뀌면 연관 문서(계획/스펙/로그)를 함께 갱신한다.
4. 상충되는 기술 결정이 있으면 최신 결정 1개만 남기고 이전 결정은 변경 이력에 남긴다.

## 4. 변경 절차
1. 변경 요청 수신
2. 영향 문서 식별
3. 문서 수정
4. 변경 이력 업데이트
5. 로그 문서(`docs/logs/YYYY-MM-DD.md`) 기록

## 5. 이력 기록 포맷
- 기록 위치: 본 문서 하단 `변경 이력`
- 기록 항목:
  - 수정일자(YYYY-MM-DD HH:mm, TZ 포함)
  - 수정자
  - 변경 대상 문서
  - 수정 요약
  - 반영 상태(완료/진행중)

## 6. 문서 반영 규칙
- 반영 누락 방지 체크:
  - `docs/specs` (기능/스키마/아키텍처)
  - `docs/logs` (작업 로그)
  - `docs/rules` (정책/규칙)
- 3개 중 1개라도 영향이 있으면 함께 업데이트 검토를 수행한다.

## 7. 예외 규칙
- 임시 메모/실험 문서는 이력 기록을 생략할 수 있다.
- 단, 임시 문서가 공식 문서로 승격될 경우 이력 규칙을 즉시 적용한다.

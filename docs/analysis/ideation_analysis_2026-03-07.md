## 2. 기획 핵심 요약
- 제품 비전:
  - 텍스트 중심 도감을 넘어서 `실물 스캔 + 보이스 + AI 대화 + AR`를 결합한 멀티미디어 포켓몬 도감 앱.
- 핵심 사용자 가치:
  - 수집품을 즉시 디지털 데이터로 연결.
  - 포켓몬 정보를 청각/시각적으로 소비.
  - 복잡한 진화/상성 정보를 AI 코칭으로 빠르게 이해.
- 데이터 범위:
  - 도감 본종 + 변형(리전폼, 메가진화, 거다이맥스 등)을 포함하는 대규모 확장 데이터 전제.

## 3. 기능별 파악 결과
- 로토무 AI 스캔:
  - 인형/카드/굿즈 인식.
  - 카드 OCR + 게임 능력치 대조.
  - 형태 구분 정확도(리전폼/메가/패러독스)가 성공의 핵심.
- 보이스/사운드 라이브러리:
  - 애니메이션 성우 보이스 + 생태 사운드 이중 모드.
  - 도감 상세에서 청취형 콘텐츠 강화 가능.
- AI 에이전트:
  - 포켓몬 페르소나 대화.
  - 진화 조건 추적(걸음 수, 기술 사용 횟수 등)형 코칭.
- 3D/AR:
  - 실물 크기 체감형 렌더링.
  - 포토 모드, 장소 기반 추천 확장 여지 존재.

## 4. 기술/아키텍처 파악
- 데이터 모델:
  - `pokemon_id + form_id` 복합 식별 구조가 필수.
  - 폼/세대/지역/타입/특성/진화 조건을 분리 정규화하는 방향이 타당.
- 상성/계산 엔진:
  - 18타입 배율 계산과 전투 중 타입 변화 대응 필요.
- 확장성:
  - 신규 세대/DLC 반영을 고려한 반정형(JSONB 등) 보조 구조 제안이 현실적.

## 5. UI/UX 방향 파악
- 메인 진입:
  - 스캔 버튼 중심의 즉시 행동 UI.
- 탐색 구조:
  - 세대/지역/폼 필터와 컬렉션 보드 중심.
- 차별 포인트:
  - 단순 정보 나열보다 `스캔-대화-청취-AR`의 연속 경험 설계가 중요.

## 6. 리스크 및 보완 포인트
- 데이터 신뢰성:
  - 문서 간 일부 수치/명칭 불일치 가능성 존재.
  - 외부 출처 기반 내용은 확정 데이터와 추정 데이터를 분리 표기 필요.
- 권리/라이선스:
  - 성우 음성, 캐릭터 음성, 에셋 사용 권한 체계 확인 필수.
- 구현 난이도:
  - 스캔 정확도와 AR 품질이 초기 만족도를 크게 좌우.
  - 멀티 기능 동시 개발 시 일정 지연 위험.

## 7. 실행 우선순위 제안
1. `MVP 정의`: 스캔 + 기본 도감 + 상성 계산 + 최소 대화 기능.
2. `데이터 스키마 고정`: ID 체계, 폼 구조, 진화 트리, 인덱스 설계 먼저 확정.
3. `모델/콘텐츠 분리`: 인식 모델 업데이트와 도감 콘텐츠 배포 파이프라인 분리.
4. `UI 프로토타입`: 핵심 플로우(스캔→상세→컬렉션) 우선 검증.
5. `2차 확장`: 보이스 고도화, AR 연출, 고급 배틀 코칭 순차 적용.

## 8. 결론
- ideation 문서군은 기능 확장성과 팬 경험 측면에서 방향성이 명확하다.
- 성공 조건은 `정확한 데이터 체계`, `초기 UX 완성도`, `권리/운영 리스크 제어`의 3축 관리다.
- 다음 단계는 MVP 범위 고정과 데이터 사전(스키마+용어+출처) 통합이다.
